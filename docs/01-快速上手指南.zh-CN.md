## 1. 什么是 CodePilot

CodePilot 是一个命令行工具，帮你把自然语言需求自动转化为可执行的任务。它串联了软件开发的全流程：

```
你说 "实现用户登录" → CodePilot 澄清需求 → 制定计划 → 写代码 → 跑测试 → 代码审查 → 报告结果
```

**核心能力：**

- 用中文或英文描述需求，自动拆分并执行
- 内置 planner（规划）、builder（编码）、reviewer（审查）三角色协作
- 支持 Claude、Codex、OpenCode 三种 AI 引擎，自动兜底切换
- Web UI 面板、飞书机器人、Webhook 多种交互方式
- 定时巡检、自动修复、项目健康检查

**适用场景：**

- 个人开发者：从想法到代码的快速通道
- 小团队：统一工作流和代码审查标准
- AI 自动化：为其他 AI Agent 提供标准化的任务投递接口

## 2. 安装

> **平台说明**：CodePilot 目前在 **Windows** 和 **Linux** 上测试通过。**macOS 未经过充分测试**，实际使用可能存在较多 bug。建议 macOS 用户通过虚拟机或 Docker 使用，或等待后续适配。

### 方式一：pip 安装（推荐）

```bash
pip install codepilot
```

### 方式二：二进制安装

从 [Releases](https://gitee.com/shuai_dd/CodePilot/releases) 下载对应平台的二进制文件：

```bash
# Windows
codepilot binary install --binary ./codepilot-windows-amd64.exe

# Linux
codepilot binary install --binary ./codepilot-linux-amd64
```

### 验证安装

```bash
codepilot --version
# 输出：codepilot, version 0.7.4
```

## 3. 首次配置

### 3.1 初始化项目

进入你的代码仓库，运行：

```bash
cd /path/to/your/project
codepilot init .
```

这会创建 `AGENTS.toml` 配置文件并将项目注册到 CodePilot。

### 3.2 项目 setup

```bash
codepilot setup .
codepilot doctor --project <项目名> --services
```

`setup` 准备 `.codepilot` 骨架目录和默认配置。`doctor` 检查环境和服务状态。

### 3.3 配置 AI Provider

编辑项目根目录的 `AGENTS.toml`，至少配置一个 AI provider：

```toml
[providers.deepseek]
enabled = true
api_key = "sk-xxxxxxxxxxxxxxxx"    # 替换为你的 API Key
base_url = "https://api.deepseek.com"
complex_model = "deepseek-v4-pro"   # 复杂任务用
simple_model = "deepseek-v4-flash"  # 简单任务用
```

也支持 OpenAI 或其他兼容接口：

```toml
[providers.openai]
enabled = true
api_key = "sk-xxxxxxxxxxxxxxxx"
base_url = "https://api.openai.com/v1"
model = "gpt-4o"
```

> **提示**：API Key 也可以放在 `~/.codepilot.secrets.toml` 中避免提交到 Git。

### 3.4 生成完整配置文件

如果不想手写，用交互式向导生成：

```bash
codepilot config init          # 项目级
codepilot config init --global # 全局默认
codepilot config validate      # 验证配置是否正确
```

## 4. 第一个需求

### 4.1 提交需求

初始化完成后，直接用自然语言提交需求：

```bash
codepilot "给 README.md 增加安装说明章节"
```

CodePilot 会自动：
1. 分析需求
2. 拆分为子任务（如果需要）
3. 规划执行顺序
4. 调用 AI 引擎执行
5. 审查结果

### 4.2 查看执行结果

```bash
# 查看项目整体状态
codepilot status -p <项目名> -v

# 查看最近活动
codepilot trace -p <项目名> --limit 10

# 查看具体任务
codepilot task show <task_id>

# 查看任务日志
codepilot task logs <task_id> --tail 50
```

### 4.3 只用语言交互

`go` 命令是显式的自然语言入口，可以问任何项目相关问题：

```bash
# 询问项目状态
codepilot go "当前项目有多少任务，完成了多少" -p <项目名>

# 询问代码问题
codepilot go "这个项目的测试是怎么组织的" -p <项目名>

# 执行操作
codepilot go "修复任务重试逻辑并补测试" -p <项目名>
```

## 5. 日常工作流

### 5.1 标准流程：澄清 → 计划 → 执行

对于复杂需求，建议分步走：

```bash
# 第一步：澄清需求（生成需求规格）
codepilot clarify -p myproject "用户登录支持手机验证码" --json

# 第二步：生成执行计划（不执行）
codepilot plan -p myproject "实现手机验证码登录" --json

# 第三步：审查计划后，自动执行
codepilot auto -p myproject -t "实现手机验证码登录"
```

### 5.2 快速探索

在不改代码的情况下了解项目：

```bash
# 探索项目结构和代码
codepilot explore -p myproject --prompt "路由是怎么组织的" --json

# 查询 Wiki 知识库
codepilot wiki query -p myproject "构建命令" --json

# 添加项目记忆
codepilot note add -p myproject "验证命令是 pytest tests -q"
codepilot note add -p myproject --priority "数据库用 SQLite，不需要安装服务"
```

### 5.3 代码审查

```bash
# 审查最近的变更
codepilot "review 最近 3 个 commit" -p myproject

# 自动修复构建问题
codepilot build-fix -p myproject --task-id <task_id> --json
```

### 5.4 任务管理

```bash
# 查看任务
codepilot task find "登录" -p myproject              # 搜索
codepilot task find "" -p myproject --status failed  # 查看失败任务

# 操作任务
codepilot task stop <task_id>     # 停止运行中的任务
codepilot task retry <task_id>    # 重试失败任务
codepilot task resume <task_id>   # 恢复暂停的任务
codepilot task cancel <task_id>   # 取消任务
codepilot task archive <task_id>  # 归档已完成任务
codepilot task rm <task_id>       # 删除任务
```

## 6. 配置详解

`AGENTS.toml` 是 CodePilot 的核心配置文件。以下按使用频率从高到低介绍。

### 6.1 Provider 配置（必配）

```toml
[providers.deepseek]
enabled = true
api_key = "sk-xxx"
base_url = "https://api.deepseek.com"
complex_model = "deepseek-v4-pro"    # builder / reviewer 用
simple_model = "deepseek-v4-flash"   # planner / triage 用
```

支持多个 provider，CodePilot 会按 `fallback_cli_order` 自动切换。

### 6.2 Agent 配置

```toml
[agents]
# 留空 = 使用默认值；也可以按场景指定
planner = ""     # 负责需求分析和任务拆分
builder = ""     # 负责代码编写
reviewer = ""    # 负责代码审查

[agents.commands]
# 自定义 CLI 命令路径
claude = "claude"
codex = "codex"
opencode = "opencode"
```

### 6.3 自动化配置

```toml
[automation]
# Agent 输出语言：en（英文）/ zh-CN（简体中文）
agent_language = "zh-CN"

# 工作区有未提交改动时的策略
# stop   = 停止执行（默认，最安全）
# commit = 自动提交
# stash  = 暂存后继续
preflight_dirty_worktree = "stop"

# CLI 引擎优先级，前面不可用时自动退化
fallback_cli_order = ["claude", "codex", "opencode"]
```

### 6.4 定时任务（Scheduled Agent）

让 CodePilot 定期执行检查：

```toml
[automation.scheduled_agents.task_health]
enabled = true
agent = "codex"
interval = "10m"                              # 每 10 分钟
# schedule = "0 9 * * *"                      # 或 Cron 表达式
prompt = "Review local CodePilot task status and summarize risks."
max_cost_usd = 0.10                           # 单次成本上限
max_daily_cost_usd = 0.50                     # 每日成本上限
```

内置三个默认 scheduled agent：
- `task_health`：任务健康检查
- `daily_summary`：日报摘要
- `auto_inspect`：轻量巡检

```bash
codepilot scheduled list -p myproject
codepilot scheduled run-once task_health -p myproject --dry-run
```

### 6.5 事件触发任务

```toml
[automation.event_agents.failed_task_triage]
enabled = false
trigger = "task.failed"                       # 任务失败时触发
agent = "codex"
prompt = "Task {{ task_id }} failed with {{ error_message }}. Suggest the smallest repair."
max_cost_usd = 0.10
```

### 6.6 通知配置

```toml
[notifications]
webhook_url = "https://open.feishu.cn/open-apis/bot/v2/hook/xxxx"
provider = "feishu"
enabled = true
```

## 7. 常用场景

### 7.1 新功能开发

```bash
# 1. 描述需求
codepilot "实现用户收货地址的增删改查接口"

# 2. 查看任务拆分结果
codepilot task find "收货地址" -p myproject --json

# 3. 检查执行结果
codepilot task logs <task_id> --tail 50

# 4. 运行测试确认
pytest tests/ -q
```

### 7.2 Bug 修复

```bash
# 1. 描述 Bug
codepilot go "修复订单金额计算精度问题，用 Decimal 替代 float" -p myproject

# 2. 如果自动修复不理想
codepilot build-fix -p myproject --task-id <task_id> \
  --verify-command "pytest tests/test_order.py -q" --json
```

### 7.3 项目巡检

```bash
# 启动后台巡检
codepilot inspect -p myproject

# 查看巡检报告
codepilot inspect -p myproject --status

# 单次全面检查
codepilot doctor --project myproject --services --json
```

### 7.4 代码重构

```bash
# 先用 explore 了解现状
codepilot explore -p myproject \
  --prompt "分析 data_access 模块的耦合关系，给出拆分建议"

# 再提交重构需求
codepilot "按照 explore 的建议拆分 data_access 模块"
```

### 7.5 多项目管理

```bash
# 列出所有注册项目
codepilot status

# 切换项目（通过 -p 参数）
codepilot status -p project-a -v
codepilot status -p project-b -v

# 查看全局配置
codepilot config validate --global
```

## 8. Web UI 与飞书

### 8.1 启动 Web UI

```bash
# 启动并在浏览器打开
codepilot ui

# 后台启动
codepilot ui start

# 查看运行状态
codepilot ui status

# 查看日志
codepilot ui logs --tail 100

# 重启
codepilot ui restart
```

Web UI 默认监听 `http://localhost:8765`，可通过环境变量修改：

```bash
# Windows PowerShell
$env:CODEPILOT_WEBUI_PORT = "8888"
codepilot ui

# Linux / macOS
CODEPILOT_WEBUI_PORT=8888 codepilot ui
```

### 8.2 飞书机器人

配置 `AGENTS.toml`：

```toml
[feishu_bot]
enabled = true
app_id = "cli_xxx"
app_secret = ""
default_project = "myproject"
```

密钥放 `.codepilot.secrets.toml`（不要提交到 Git）：

```toml
[feishu_bot]
app_secret = "your-app-secret"
```

启动：

```bash
npm install           # 安装飞书 Node SDK（首次）
codepilot feishu start
```

飞书中常用文本指令：

```text
projects              # 查看项目列表
use myproject         # 切换当前项目
tasks myproject       # 查看任务
detail 42             # 查看任务 42 详情
stop 42               # 停止任务
run myproject         # 手动触发执行
当前项目状态怎么样      # 自然语言查询
```

## 9. 进阶功能

### 9.1 Hook 系统

Hook 让你在 AI 调用的关键节点注入自定义逻辑：

```bash
# 查看当前项目的 Hook 规划
codepilot hook plan -p myproject --json

# 验证 Hook 配置
codepilot hook validate -p myproject --json

# 测试 Hook
codepilot hook test -p myproject --provider codex \
  --event agent.prompt.submitted --json
```

### 9.2 Webhook 接收外部任务

```bash
codepilot webhook --host 127.0.0.1 --port 8765
```

`POST /tasks` 示例：

```json
{
  "project": "myproject",
  "title": "来自 CI 的构建修复任务",
  "content": "CI 报错：test_login 失败，请修复",
  "priority": "P1",
  "agent": "codex"
}
```

### 9.3 Skill 系统

复用和共享工作流模板：

```bash
# 列出可用 Skill
codepilot skill list -p myproject --json

# 搜索
codepilot skill search "code review" -p myproject --json

# 查看详情
codepilot skill show build-fix -p myproject --json

# 启用/禁用
codepilot skill enable build-fix -p myproject
```

### 9.4 事件系统

```bash
# 查看事件结构定义
codepilot event schema --json

# 注册事件监听
codepilot event register -p myproject \
  --name audit --type jsonl \
  --path .codepilot/events/audit.jsonl \
  --event doctor.checked
```

### 9.5 发布流程

```bash
# 构建二进制
codepilot binary build

# 准备发布
codepilot binary prepare --version 0.8.0

# 验证
codepilot binary verify

# 发布
codepilot binary release --build-current
```

## 10. 常见问题

### 命令不存在

如果提示命令找不到，旧命令已迁移：

| 旧命令 | 新命令 |
|--------|--------|
| `codepilot show <id>` | `codepilot task show <id>` |
| `codepilot logs <id>` | `codepilot task logs <id>` |
| `codepilot stop <id>` | `codepilot task stop <id>` |
| `codepilot webui ...` | `codepilot ui ...` |
| `codepilot release ...` | `codepilot binary ...` |

### 任务一直不执行

1. 检查项目状态：`codepilot status -p <项目名> -v`
2. 查看 daemon 是否运行：`codepilot daemon -p <项目名> --status`
3. 手动触发一次：`codepilot run -p <项目名> --once`

### API Key 报错

1. 确认 `AGENTS.toml` 中对应 provider 的 `enabled = true`
2. 确认 `api_key` 已填写且未过期
3. 确认 `base_url` 格式正确（不要末尾带 `/v1/chat/completions`）
4. 运行 `codepilot exec -p <项目名> --provider deepseek --dry-run --json -- codex --version` 测试连通性

### 飞书机器人不回复

1. 确认 `npm install` 已运行
2. 检查飞书应用凭证：`codepilot feishu status`
3. 查看日志：`codepilot feishu logs --tail 50`

### 模型回答是英文

在 `AGENTS.toml` 的 `[automation]` 中设置：

```toml
agent_language = "zh-CN"
```

### 输出太多看不清

很多命令支持 `--json` 输出结构化数据，方便用 `jq` 过滤：

```bash
codepilot status -p myproject --json | python -m json.tool
codepilot task find "登录" -p myproject --json
```

### 环境隔离

设置 `CODEPILOT_HOME` 环境变量可以隔离开发环境和生产环境：

```bash
# 开发环境
export CODEPILOT_HOME="$HOME/.codepilot-dev"

# Windows
set CODEPILOT_HOME=%USERPROFILE%\.codepilot-dev
```
