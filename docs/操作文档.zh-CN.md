# CodePilot 操作文档

## 1. 日常操作

### 1.1 初始化与提交需求

```bash
codepilot init .
codepilot "实现自动拆分和自动执行工作流"
```

### 1.2 任务状态与详情

```bash
codepilot status -p <项目名> -v
codepilot task show <task_id>
codepilot task logs <task_id> --tail 80
```

### 1.3 任务干预

```bash
codepilot task stop <task_id>
codepilot task retry <task_id>
codepilot task cancel <task_id>
codepilot task archive <task_id>
```

### 1.4 添加任务（add）的强制规则

> CodePilot 的预期使用模式：**人工只走需求**（`codepilot "需求文本"`），让规划器自己拆任务；**add 命令主要给 AI / 智能体使用**。

无论是人还是 AI 调用 `add`，content 必须模板合规，**没有空正文占位通道**：

| 场景 | 行为 |
| :--- | :--- |
| `codepilot add -t "标题"` | 必须由 `--agent` 指定的 AI 生成模板合规 content；缺章节立即拒绝。 |
| `codepilot add -f tasks.txt`（每行一个标题） | 每行都走一次 AI 生成 + 校验；任一行失败整批回滚。 |
| `codepilot add -f tasks.json` | 每条必须自带 `content`，按 `codepilot ai template --format json` 给的 schema 准备；缺章节直接拒绝。 |
| `codepilot add -f tasks.md` | 多个任务用 `---` 分隔，每段都是完整 task-template；缺章节直接拒绝。 |

`--no-ai` / `--allow-empty` 这两个旧标志已经废除。如果你历史上写过它们，请：

```bash
# 拿到当前模板字段 schema（机器可读）
codepilot ai template --format json

# 中文填充指南（含示例）
codepilot ai template --format guide

# 原始 task-template.md
codepilot ai template
```

## 2. 项目级执行与巡检

### 2.1 执行队列

```bash
codepilot run -p <项目名>
codepilot daemon -p <项目名>
codepilot daemon -p <项目名> --status
codepilot daemon -p <项目名> --stop
```

### 2.2 巡检

```bash
codepilot inspect -p <项目名> --once
codepilot inspect -p <项目名>
codepilot inspect -p <项目名> --status
codepilot inspect -p <项目名> --stop
```

```bash
codepilot ui
```

后台服务：

```bash
codepilot ui start
codepilot ui status
codepilot ui logs --tail 100
codepilot ui stop
```

## 4. Webhook 与飞书通知

启动本地 webhook 服务，接收外部系统投递任务：

```bash
codepilot webhook --host 127.0.0.1 --port 8765
```

向 `POST /tasks` 发送 JSON，可写入 backlog：

```json
{
  "project": "demo",
  "title": "来自外部系统的任务",
  "content": "任务正文",
  "priority": "P1",
  "agent": "codex"
}
```

如果要把任务状态通知发到飞书，在项目 `AGENTS.toml` 里配置：

```toml
[notifications]
webhook_url = "https://open.feishu.cn/open-apis/bot/v2/hook/xxxx"
provider = "feishu"
webhook_secret = ""
enabled = true
```

说明：

- `provider` 支持 `auto / feishu / wecom / generic`，接飞书时建议显式写 `feishu`。
- `webhook_secret` 仅飞书机器人开启“签名校验”时需要填写；未开启可留空。
- 也可用环境变量临时覆盖：`CODEPILOT_WEBHOOK_URL`、`CODEPILOT_WEBHOOK_PROVIDER`、`CODEPILOT_WEBHOOK_SECRET`、`CODEPILOT_WEBHOOK_ENABLED`。

### 4.2 飞书企业应用长连接机器人

本地没有公网回调入口时，使用飞书企业应用长连接模式。运行时依赖官方 Node SDK，不依赖 `lark-cli`。

项目 `AGENTS.toml`：

```toml
[feishu_bot]
enabled = true
app_id = "cli_xxx"
app_secret = "xxx"
node_command = "node"
default_project = "demo"
command_prefix = ""
```

安装依赖并启动：

```bash
npm install
codepilot feishu start
codepilot feishu status
codepilot feishu logs --tail 100
codepilot feishu stop
```

飞书里手动发命令：

```text
projects
tasks demo
detail 123
stop 123
retry 123
run demo
status demo
```

说明：

- `codepilot feishu start` 启动的是后台 supervisor，不是一次性脚本；长连接 worker 异常退出后会自动重启。
- 当 `[feishu_bot].enabled = true` 时，启动 `codepilot ui` / `codepilot ui start` / `codepilot daemon --foreground` 也会自动确保飞书服务已在后台运行。
- 这属于 CodePilot 进程级自启动；如果你要“开机自启”，还需要再挂到系统计划任务或常驻服务里。

## 5. 发布操作

### 4.1 构建与安装

```bash
codepilot binary build
codepilot binary build --install
codepilot binary install --binary <path-to-binary>
codepilot binary where
```

### 4.2 发布目录

```bash
codepilot binary release --build-current
codepilot binary verify
codepilot binary prepare --version <版本号>
```

## 6. 排障手册

### 5.1 命令不存在（旧入口）

现象：提示 `命令 xxx 已移除`

处理：

- `show/logs/stop/retry/find/...` 改为 `task <subcommand>`
- `release ...` 改为 `binary ...`
- `webui ...` 改为 `ui <start|status|logs|stop|restart>`

### 5.2 任务卡住或无输出

顺序建议：

1. `codepilot status -p <项目名> -v`
2. `codepilot task logs <task_id> --full`
3. 必要时 `codepilot task stop <task_id>`
4. 修复后 `codepilot task retry <task_id>`

### 5.3 环境检查

```bash
codepilot doctor
codepilot doctor --json
```

## 7. 结构化调用契约

命令支持统一 envelope：

```json
{
  "ok": true,
  "command": "status",
  "data": {}
}
```

失败时会包含 `error` 字段（`message` / `code`）。
