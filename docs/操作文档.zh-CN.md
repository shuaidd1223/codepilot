# CodePilot 操作文档

语言版本：中文 | [English](操作文档.en-US.md)

## 1. 日常入口

### 1.1 初始化项目

```bash
codepilot setup . --dry-run --json
codepilot setup .
codepilot doctor --project <项目名> --services
```

`setup` 会准备项目级 `.codepilot` 骨架、同步配置并注册项目；`--dry-run` 只报告动作。老的 `init .` 仍可用于“注册项目 + 生成 AGENTS.toml”的基础初始化。

```bash
codepilot init .
codepilot init D:\repo -n demo
```

### 1.2 提交需求

```bash
codepilot "实现自动拆分和自动执行工作流"
codepilot go "修复任务重试逻辑并补测试" -p <项目名>
codepilot auto -p <项目名> -t "高层目标" --plan-only
```

人工日常优先使用自然语言入口，让规划器拆任务。`add` 主要给外部 AI / 自动化系统直接投递已规划任务使用。

### 1.3 OpenCode 会话入口

询问项目状态、任务统计、完成度、失败任务、运行中任务、服务状态时，可以直接问：

```bash
codepilot go "当前项目有多少任务，完成了多少" -p <项目名>
codepilot go "当前项目状态怎么样" -p <项目名>
```

`chat`、Web UI 会话和飞书自由文本统一进入 OpenCode + CodePilot MCP 会话。可以直接输入需求、问题或操作意图，由 OpenCode 在会话里调用 CodePilot 工作流能力：

```text
当前项目状态怎么样
优化飞书任务面板
删除失败任务前先列出候选并说明风险
```

日常会话直接输入自然语言即可。需要严格产出规格或计划 artifact 时，再显式调用 `clarify`、`plan`、`/api/requirements` 等入口。

OpenCode 会话使用 CodePilot 隔离运行时：

- 配置、TUI 插件、agent、commands 写入用户级 `~/.codepilot/opencode/<项目标识>/`。
- 不在业务项目目录生成 `.codepilot/opencode/`。
- 会话数据和模型选择与用户自己直接运行的 `opencode` 隔离。
- TUI 中切换过模型后，CodePilot 会保存为该项目默认模型，新会话继续沿用。

## 2. 澄清、计划与只读取证

### 2.1 需求规格

```bash
codepilot clarify -p <项目名> "改进 doctor" --json
codepilot clarify --quick -p <项目名> "优化任务面板"
```

`clarify` 只生成执行前需求规格 artifact，不创建 backlog、不启动执行器。

### 2.2 可审查计划

```bash
codepilot plan -p <项目名> "新增 explore" --json
codepilot plan -p <项目名> --from-spec .codepilot/specs/example.md --json
```

`plan` 输出执行顺序、文件范围、风险、验证矩阵和任务候选，默认不创建任务。

### 2.3 只读探索

```bash
codepilot explore -p <项目名> --prompt "find task template" --json
codepilot explore -p <项目名> "recent failed task logs"
```

`explore` 只读取项目文件、Git、wiki、任务日志摘要和 inspect 信号。修改、安装、启动服务或执行测试类请求应改走普通 workflow。

### 2.4 Wiki 与记忆

```bash
codepilot wiki add -p <项目名> --title "构建命令" --body "pytest tests"
codepilot wiki query -p <项目名> "构建" --json
codepilot wiki update -p <项目名> --slug build --body "pytest -q" --json
codepilot wiki ingest --from trace -p <项目名> --json
codepilot wiki lint -p <项目名> --json
```

```bash
codepilot note add -p <项目名> "当前验证命令是 pytest tests"
codepilot note add -p <项目名> --priority "项目使用 Python 3.11"
codepilot note show -p <项目名> --json
codepilot note prune -p <项目名> --days 7
```

不要把 secret、token、密码、飞书 `app_secret` 或临时大段日志写入 wiki/note。

## 4. `add` 的强制规则

`add` 是直接写 backlog 的低层入口。人工要新增工作时，优先使用：

```bash
codepilot "需求文本"
```

外部 AI / 自动化系统如果必须直接投递任务，先读取模板：

```bash
codepilot ai template --format json
codepilot ai template --format guide
codepilot ai template
```

投递方式：

```bash
codepilot add -p <项目名> -t "任务标题"
codepilot add -p <项目名> -f tasks.json
codepilot add -p <项目名> -f tasks.md
codepilot add -p <项目名> -f tasks.txt
```

规则：

- `add -t` 和 `tasks.txt` 会调用 `--agent` 指定的 AI 生成模板合规 content。
- `tasks.json` 每条必须自带模板合规 `content`。
- `tasks.md` 每个 `---` 分隔段都必须是完整 task-template。
- `--no-ai` / `--allow-empty` 已废除，没有空正文占位通道。

## 5. 执行队列与巡检

### 5.1 执行 backlog

```bash
codepilot run -p <项目名>
codepilot run -p <项目名> --once
codepilot run -p <项目名> --limit 3 --executor builtin --no-auto-commit
```

内置执行器预检发现主工作区已有未提交改动时，默认停止执行并把任务留在 backlog，不消耗重试次数。可在 `AGENTS.toml` 中配置：

```toml
[automation]
# stop = 停止执行；commit = 预检提交现有改动；stash = stash 现有改动并写入任务日志/运行记录
preflight_dirty_worktree = "stop"
```

### 5.2 后台 daemon

```bash
codepilot daemon -p <项目名>
codepilot daemon -p <项目名> --status
codepilot daemon -p <项目名> --stop
codepilot daemon -p <项目名> --foreground
```

### 5.3 巡检

```bash
codepilot inspect -p <项目名> --once
codepilot inspect -p <项目名> --dry-run --json
codepilot inspect -p <项目名> --once --dry-run --write-workflow --json
codepilot inspect -p <项目名> --status
codepilot inspect -p <项目名> --stop
```

`--write-workflow` 会把只读巡检结果写入 `.codepilot/context/inspect-*.json`，并让 `workflow next --list --json` 暴露 `create_inspect_tasks`、`promote_inspect_report_<candidate_id>`、`plan_from_inspect` 等安全动作。普通 `--dry-run` 不写 workflow 状态。

### 5.4 失败修复闭环

```bash
codepilot build-fix -p <项目名> --json
codepilot build-fix -p <项目名> --task-id <task_id> --verify-command "pytest tests/test_x.py -q" --json
codepilot build-fix -p <项目名> --task-id <task_id> --dry-run
```

## 6. Web UI、飞书与 Webhook

### 6.1 Web UI

```bash
codepilot ui
codepilot ui --no-open --port 8877
codepilot ui start
codepilot ui status
codepilot ui logs --tail 100
codepilot ui restart
codepilot ui stop
```

### 6.2 Webhook

```bash
codepilot webhook --host 127.0.0.1 --port 8765
```

`POST /tasks` 示例：

```json
{
  "project": "demo",
  "title": "来自外部系统的任务",
  "content": "任务正文",
  "priority": "P1",
  "agent": "codex"
}
```

飞书 webhook 通知配置：

```toml
[notifications]
webhook_url = "https://open.feishu.cn/open-apis/bot/v2/hook/xxxx"
provider = "feishu"
webhook_secret = ""
enabled = true
```

### 6.3 飞书长连接机器人

项目 `AGENTS.toml`：

```toml
[feishu_bot]
enabled = true
app_id = "cli_xxx"
app_secret = ""
node_command = "node"
default_project = "demo"
command_prefix = ""
```

同目录 `.codepilot.secrets.toml`：

```toml
[feishu_bot]
app_secret = "xxx"
```

运行：

```bash
npm install
codepilot feishu start
codepilot feishu status
codepilot feishu logs --tail 100
codepilot feishu stop
codepilot feishu run
```

飞书常用文本：

```text
projects
use demo
tasks demo
detail 123
stop 123
retry 123
cancel 12 13
archive 20,21
delete 30 31
run demo
status demo
当前项目状态怎么样
优化飞书任务面板
修复一个明确的小问题，先说明计划再执行
```

飞书明确命令仍由 CodePilot 本地路由处理；其他自由文本会进入当前项目的 OpenCode 会话。没有当前项目时，机器人会先返回项目选择卡片。

## 7. 事件、Hook、Provider 与 Skill

### 7.1 事件 sink

```bash
codepilot event schema --json
codepilot event list -p <项目名> --json
codepilot event register -p <项目名> --name audit --type jsonl --path .codepilot/events/audit.jsonl --event doctor.checked
codepilot event enable -p <项目名> audit --json
codepilot event test -p <项目名> --event doctor.checked --json
codepilot event disable -p <项目名> audit --json
```

### 7.2 Hook registry

```bash
codepilot hook plan -p <项目名> --json
codepilot hook validate -p <项目名> --json
codepilot hook test -p <项目名> --provider codex --event agent.prompt.submitted --json
codepilot hook logs -p <项目名> --json
codepilot hook install -p <项目名> --dry-run
codepilot hook uninstall -p <项目名> --dry-run
```

当前 hook 命令只规划和验证项目级 wrapper，不修改真实全局 hooks。

### 7.3 Provider exec

```bash
codepilot providers
codepilot providers --available
codepilot exec -p <项目名> --provider codex --dry-run --json -- codex --version
codepilot exec -p <项目名> --provider custom --json -- python -c "print(123)"
```

### 7.4 Skill catalog

```bash
codepilot skill list -p <项目名> --json
codepilot skill search quality -p <项目名> --json
codepilot skill show build-fix -p <项目名> --json
codepilot skill enable build-fix -p <项目名> --json
codepilot skill disable build-fix -p <项目名> --json
codepilot skill run ralplan -p <项目名> --provider codex --input "新增 wiki context" --json
```

## 9. 排障手册

### 9.1 命令不存在

如果提示旧命令已移除：

- `show/logs/stop/retry/find/...` 改为 `task <subcommand>`
- `release ...` 改为 `binary ...`
- `webui ...` 改为 `ui <start|status|logs|stop|restart>`

### 9.2 任务卡住或无输出

```bash
codepilot status -p <项目名> -v
codepilot trace -p <项目名> --task <task_id> --json
codepilot task logs <task_id> --full
codepilot task stop <task_id>
codepilot task retry <task_id>
```

### 9.3 失败任务需要修复

```bash
codepilot build-fix -p <项目名> --task-id <task_id> --dry-run
codepilot build-fix -p <项目名> --task-id <task_id> --verify-command "pytest tests/test_x.py -q" --json
```

### 9.4 环境与服务检查

```bash
codepilot doctor
codepilot doctor --json
codepilot doctor --project <项目名> --json
codepilot doctor --project <项目名> --services --json
```

`doctor --fix` 只执行保守项目级修复，例如准备配置和 `.codepilot` 目录，不修改真实 hooks。

### 9.5 OpenCode 模型或权限不符合预期

模型来源按以下顺序生效：

1. CodePilot 保存的项目级 OpenCode 模型选择。
2. 当前项目 `AGENTS.toml` 中的 `[providers.<name>]` 配置。
3. OpenCode 自身可用的默认模型。

如果 TUI 新会话又回到内置免费模型，先在 TUI 中重新选择一次目标模型并正常退出；CodePilot 会把这次选择同步为项目默认模型。

项目级权限配置示例：

```toml
[opencode.permission]
mode = "ask"         # 默认，危险操作逐项确认
# mode = "full_access"  # 信任当前项目时可跳过确认
# mode = "custom"       # 使用自定义 rules

[opencode.permission.rules]
bash = "ask"
edit = "ask"
write = "ask"
webfetch = "ask"
```

OpenCode 第一层权限之外，CodePilot MCP 工具仍有二次校验，例如 `exec`、任务写入、飞书、Webhook、Hook 等高风险入口会继续按工具规则限制。
