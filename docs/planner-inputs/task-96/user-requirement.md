# Task #96 用户需求输入

## 需求描述（要做什么）
- 补齐自动规划阶段的输入，确保规划器在拆分任务前同时拿到两份信息：
  1. 用户需求原文（目标、动机、成功标准）。
  2. 侦察员结构化报告（相关文件、现有实现位置、风险与依赖）。

## 需求动机（为什么做）
- 上轮执行中 builder 只在终端输出了“补齐稿”，但没有把输入写入仓库文件，导致 reviewer 无法核对输入是否齐全、是否可复用、是否与当前分支代码一致。

## 成功标准（如何判定完成）
- 在仓库内存在可复用的规划输入文件，并明确记录用户需求。
- 在仓库内存在结构化侦察报告，至少包含：
  - 目标改动文件清单。
  - 相关现有实现位置（`file_path:line`）。
  - 已识别风险与依赖。
- 侦察报告覆盖范围与本任务需求一致，不扩展到无关目标。
