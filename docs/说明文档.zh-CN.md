# CodePilot 说明文档

## 1. 定位

CodePilot 是一个面向本地工程仓库的工作流编排 CLI，核心目标是把“需求 -> 任务 -> 执行 -> 交付”流程标准化。

核心能力：

- 自然语言需求入口（`codepilot "需求"` / `go` / `chat`）
- 任务生命周期管理（统一 `task` 子命令）
- 项目级后台执行与巡检（`daemon` / `inspect` / `ui`）
- AI 友好接口（`ai manifest` / `ai guide` / `--json` 契约）
- 二进制构建与发布（统一 `binary` 子命令）

## 2. 架构概览

逻辑分层：

1. 入口层：`cli.py`、`commands/*`
2. 规划与执行层：`auto_workflow`、`run`、`daemon`、`inspect`
3. 数据层：SQLite（项目、任务、日志、服务状态）
4. 展示与交互层：终端输出 + 本地 Web UI

主要目录：

- `codepilot/`：核心实现
- `codepilot/commands/`：CLI 子命令
- `codepilot/web/`：Web UI 前端资源
- `docs/`：文档
- `tests/`：测试

## 3. 命令域模型

当前命令体系按职责分组：

- 需求入口：`go` / `auto` / `chat`
- 执行调度：`run` / `daemon` / `inspect`
- 任务运维：`task ...`
- 项目管理：`init` / `project` / `status` / `cleanup` / `doctor`
- 发布与安装：`binary ...`
- AI 接入：`ai ...`
- 可视化：`ui`（含前台与后台服务子命令）

强约束：

- 任务命令统一到 `codepilot task ...`
- 发布命令统一到 `codepilot binary ...`
- `release` 顶层旧入口已移除

## 4. 配置模型

主配置文件：`AGENTS.toml`

常见配置域：

- `[project]`：项目标识、默认模式、基线分支
- `[automation]`：规划器、执行器、自动执行策略
- `[inspect]`：巡检策略
- `[agents]`：不同智能体命令映射

建议：

- 多项目统一模板化 `AGENTS.toml`
- 在 CI 或初始化脚本里固定关键字段（例如执行器、默认模式）

## 5. 数据与状态

数据库持久化关键信息：

- 项目注册信息
- 任务与依赖关系
- 执行日志和运行时状态
- 服务状态（daemon / ui / inspect）

运行期常见状态字段：

- `status`: backlog / in_progress / done / failed / cancelled / archived
- `run_phase`: builder / reviewer / dispatch 等
- `heartbeat_at` / `active_pid` / `current_log_path`

## 6. 对外集成方式

推荐从以下入口接入：

- 非交互执行：`codepilot "需求"`
- 结构化采集：`status --json`、`task show --json`、`task find --json`
- 标准命令描述：`codepilot ai manifest`
